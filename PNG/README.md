## ToLiss ECAM reference review, 2026-09-09

`toliss-ecam-reference/` contains the twelve redesigned lower-SD instrument
faces and three four-page review sheets generated by
`tools/render_toliss_ecam_reference.py`. They emulate the actual native LCD
font slots and drawing commands. All displayed numbers are **offline samples**,
not live telemetry. In particular NORMAL, oxygen/tire pressure, fuel used and
oil-quart sample values do not establish working simulator mappings. Sources
in `PIC/` are untouched. Live unmapped readings are amber XX. Both BB35/BB36
use the same renderer; confirm actual-panel appearance after a safe restart.

This folder holds two kinds of image, neither of which touches the aircraft,
the bridge, or the hardware:

- **Design sheets** (`pfd-737-*.png`) — the agreed 737 PFD design, drawn by
  `tools/build_pfd_design_png.py`. These are the drawing target.
- **Panel frames** (`pfp-frame-*.png`) — exactly what the PFP screen shows,
  produced by `tools/render_pfp_frame_png.py`, which runs the live renderer
  against an offline emulator of the PFP's native command surface. It decodes
  glyphs from the font resource the bridge actually uploads, so text and the
  static shape tiles appear exactly as they do on the panel.

The expanded display suite has a third offline-only review command:

```bash
python tools/render_coded_display_pages.py --out display-qa
```

It renders PFD APP, ND MAP 20/640, PLAN 10/40, VOR, APP and VSD, plus ENG PRI,
MFD and HYD. The PLAN pair proves that route/waypoint geometry and the two
half/full-distance circles respond to the selected zoom.
Those PNG files are QA snapshots, not live assets. The BB35/BB36 implementation
continues to draw every page from native rectangles, curves and text and does
not load any PNG at runtime.

The panel frames are how a renderer change is judged before anything is sent to
the cockpit. `pfp-frame-before-normal.png` is the page as it was before the
visual pass, kept for comparison.

The 2026-09-01 compact-value recovery fix intentionally has no new comparison
PNG: its correct settled pixels are identical. The later physical test showed
that alternating healing halves made the MAG arc swap sides, so timed PFD
healing was removed. Complete recovery is now atomic and lifecycle-only; the
122-frame long-hold regression proves that a healthy display remains complete
and compact without a timed redraw.

The later hybrid-transparency work also intentionally retains no new banking
PNG. Its generated masks are compared directly with the font resource pixel by
pixel, and its moving-background safety is checked across a pitch/bank grid by
`tools/check_pfp_hybrid_transparency.py`.

## The layout contract

| Zone | Origin and size |
| --- | --- |
| Speed tape | `90,72  70x328` |
| Altitude tape | `480,72  72x328` |
| Attitude display | `184,100  272x252`, corner radius 30 |
| Live speed window | `44,200  100x52`, chevron reaching 16 px inboard |
| Live altitude window | `480,200  102x52`, nipple reaching 14 px into its own tape |
| Vertical speed wedge | `566,116  68x220`, outer corners chamfered 34 px; left edge notched to x584 around the live box |
| Heading readout | `286,389  69x29` |
| Minimums reference | `462,404  170x29` |
| Barometer | joined value/unit run at `498,435  119x29` |
| Compass rose | centre `320,583`, radius 193 |

The common datum is `y = 226`: the attitude centre, the speed pointer, the
altitude pointer, and the vertical-speed zero all sit on that line.

Moving-scale rates, matched to the live renderer: **2.15 px per knot**, **0.22
px per foot**, 5 px per degree of pitch, and the heading arc drawn one for one
with heading. Colours are the renderer's own constants.

Operational text and numbers retain the controller's fixed 17 x 29 native
cells. On a uniform background that opaque path is fastest and remains the
normal path. If a pitch character crosses the moving horizon or rounded shell,
the renderer draws only the foreground pixels decoded from the exact slot-3
glyph instead of sending its background cell.

Slots 7/8 use 40 x 40 cells cut from one continuous 10/20-degree rung raster.
Each complete cell that belongs to one sky/earth colour stays native and
background-matched. A crossing cell uses foreground-only rectangles decoded
from the same glyph. This hybrid gives software transparency without changing
the uploaded font or depending on undocumented controller alpha.

## Conventions

- **Roll sign.** X-Plane's captain AHARS value is negative in a right bank. A
  right bank moves the aircraft roll pointer right. The numbered pitch ladder
  follows it, left-up/right-down, while the bold natural horizon is opposite,
  left-down/right-up. Left bank mirrors those directions.
- **Bank pointer.** The filled moving triangle represents the aeroplane and
  stays aimed radially at the fixed bank scale. The slip/skid marker rotates
  beneath it, aligns with it at zero slip and offsets along its tangent when
  the aircraft slips or skids.
- **Pitch-ladder centre.** Every numbered rung centre lies on the radial axis
  of that moving upward triangle. The fixed downward triangle at the top centre
  is only the zero-bank index. The bold horizon keeps its opposite bank slope.
- **Natural horizon.** The separator between sky and earth is white and rotates
  with the outside-world horizon.
- **Fixed aircraft reference.** The two opposed thick wings, inner hooks and
  small hollow centre square are black and remain fixed while attitude moves.
- **Angled strokes.** Labelled 10/20-degree rungs are three-pixel continuous
  native rasters with a centre gap, cut into cells only after the whole raster
  is built. Uniform cells are field-matched; crossing cells emit only the exact
  foreground mask. Intermediate 2.5/5-degree marks remain solid coded bars.
  The bold natural horizon remains coded because it divides two colours.
- **Tape bugs face inward** on both tapes, toward the attitude display.
- **Aircraft symbol** hooks downward at its inboard ends.
- **Minimums.** `BARO` is an altitude, so it also carries a pointer on the
  altitude tape. `RADIO` is a height above the ground, which no barometric tape
  can show, so it is text only. Both turn amber at or below the setting.

## Frame cost

The panel bills almost exactly one millisecond per HID report, so a frame's
report count is close to its frame time. With hybrid transparency, the current
40-frame differential medians are 105 reports in straight cruise, 313 through
the combined bank/climb/tape sequence, 63 under sensor jitter, 310 through the
modes/extremes sequence and one for an unchanged frame. Complete offline QA is
254 reports for normal and 307 for the 45-degree extreme. The main bank cost
remains the horizon's exact moving sky/earth edge; crossing line/text cells now
avoid opaque backgrounds with exact foreground masks.

`BLEND_HORIZON_EDGE` and the motion/recovery rung settings in the renderer are
the deliberate places to trade smoothness against frame rate. The labelled
10/20-degree rungs no longer use a chain of tiny fill commands.
